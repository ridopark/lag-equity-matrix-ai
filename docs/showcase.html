Why this needs a graph database

The question is not "who supplies Apple". It is "as of a given date, who reaches Apple within two supply-chain hops, using only filings published before that date" — a directed traversal with a per-hop validity window. One hop is a dataframe join. Two hops with a temporal predicate on every edge is a self-join per hop, and it is one AQL statement.

The LangGraph pipeline

    
One Send branch per candidate. Graph traversal and vector
      retrieval run in parallel and rejoin at context_fusion. Every run is
      checkpointed under a thread id and replayable; review is an
      interrupt() gate that halts on a contradicted verdict — this topology
      is what the pipeline actually builds, and the suite that proves it is
      test_fanout, test_checkpointing and
      test_review.
      The per-node timings below are the real durations of the AQL and ANN calls; the ordering is the
      graph's own. Once the adapters land, these become one graph.astream
      trace rather than a composed one.

Four results that looked real and were not

      
A 400-sample run reported +115 bp at z=+3.89; the full 19,867 reversed the sign. One evidence
        band showed +64 bp while the strongest band showed +1.66 bp. A ten-year run gave +27 bp at
        z=+4.53 until a coverage filter turned out to be excluding every post-2016 IPO. A corrected run
        still showed +17.95 bp until a heterogeneity test found I²=81% with the sign flipping between
        halves. Every test on this page was pre-registered — decision rule, economic threshold and
        expected power written down before the data was fetched — which is the only reason those four
        were caught rather than published.
